# helm-ci CLI

**Source:** `.github/scripts/helm-pipeline/src/helm_pipeline/`

The `helm-ci` package provides two console scripts used by the workflows. Install it from git:

```bash
python -m pip install "helm-ci @ git+https://github.com/ITlusions/ITL.Github.git@main"
```

## chart-pipeline

Entry point in `cli/chart_cli.py`, which delegates to `charts/pipeline.py`. The steps are implemented in `charts/` (chart discovery, change detection, validation, versioning, publishing) and `core/` (command runner, verified downloads, GitHub outputs).

| Command | Purpose |
|---|---|
| `changed [--base SHA] [--develop REF] [--all] [--chart NAME] [--tag TAG]` | Writes changed and affected charts to `GITHUB_OUTPUT` (used by the pipeline) |
| `setup-tools --directory DIR` | Downloads and verifies kubeconform and the helm-unittest plugin, and adds `DIR` to `GITHUB_PATH` |
| `setup-kind --directory DIR` | Downloads and verifies `kind` and `kubectl`, and adds `DIR` to `GITHUB_PATH` |
| `kind-test [CHART] --scenario NAME [--kube-version VERSION] [--cluster-name NAME] [--keep-cluster] [--dry-run]` | Creates a kind cluster, installs prerequisites and the chart for one `kind-test` scenario, runs `helm test` if hooks exist, and deletes the cluster. `--dry-run` prints the commands without running them. `--keep-cluster` leaves the cluster running after the run for debugging. `--cluster-name` (default `ci`, env `CLUSTER_NAME`) sets the cluster name. |

To reproduce a CI failure locally, run the same command from a machine with `kind`, `kubectl`, and `helm` on PATH, for example `chart-pipeline kind-test charts/my-chart --scenario minimal --kube-version 1.36.4 --cluster-name local-dev --keep-cluster`. Use `--dry-run` first to check the plan. Use a cluster name other than `ci` on a developer machine: the cleanup step deletes the cluster with the given name, so `ci` could remove an existing cluster.
| `lint-all` | Lints all charts |
| `check-requirements` | Checks requirements |
| `validate [CHART]` | Validates a chart |
| `check-version [CHART]` | Checks that `Chart.yaml` declares a version |
| `next-version [CHART]` | Writes `version`, `is-release` and `tag` to `GITHUB_OUTPUT`, computed from release tags and `Chart.yaml` |
| `render-diff [CHART] [BASE]` | Renders and diffs a chart against a base revision |
| `package [CHART] [--destination DIR]` | Packages a chart (default `dist/packages`) |
| `publish [CHART]` | Logs in, checks that the version is not in the registry, and pushes the chart. Not used by the workflows. |

## security-scan

Entry point in `cli/security_cli.py`, which delegates to `security/pipeline.py`.

| Command | Purpose |
|---|---|
| `setup-tools --directory DIR --tool {trivy,kubescape,gitleaks}` | Downloads and verifies scanner binaries (repeatable `--tool`) |
| `chart [CHART]` | Renders and scans a chart with Trivy and Kubescape |
| `repository` | Scans the repository |
| `secrets [--base REV]` | Scans for secrets with gitleaks, optionally only commits after `REV` |
| `dependencies` | Scans dependencies |

Failed scanners are recorded in `scan-errors.json` inside the report directory.

Downloads are checked against SHA-256 checksums.

### Changing pinned versions

All pins live in a single file, `src/helm_pipeline/config.yaml`, which is packaged with the CLI. To change a pin, edit the url and sha256 of the tool in that file. Each entry needs both keys.

```yaml
tools:
  trivy:
    url: https://github.com/aquasecurity/trivy/releases/download/v0.76.2/trivy_0.76.2_Linux-64bit.tar.gz
    sha256: bc0fc726e017b8927a62b2d3531d7a84ee01769daf5c99ed866dced54089fdbf
```

The url must use https, and the sha256 must be 64 lowercase hexadecimal characters. The file must have only the top-level key `tools`. An invalid entry stops the CLI with an error that names the tool.
